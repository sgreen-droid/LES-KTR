Build a very small Windows desktop application named:

LES Location Agent

PURPOSE
This application is for organization-owned Windows PCs.

Its ONLY purpose is to obtain the most accurate geographic location that Windows can provide, save that location locally, and make the result easy for Action1 RMM to read.

Do NOT build:
- a web dashboard
- a database
- a cloud backend
- user tracking features
- screenshots
- camera access
- microphone access
- browser history collection
- keystroke collection
- file collection

Keep this project extremely small, reliable, and production-oriented.

========================================================
TECHNOLOGY
========================================================

Build a native Windows 11 desktop application using:

- C#
- .NET 8 or the current appropriate supported .NET version
- Windows App SDK
- WinUI 3
- Windows.Devices.Geolocation

Target:
- Windows 11
- x64

Use Microsoft's supported Windows geolocation APIs.

Do NOT use:
- browser HTML5 geolocation
- IP address location as the primary source
- Google Maps
- external location APIs
- unsupported Windows registry tricks

The primary location source MUST be:

Windows.Devices.Geolocation.Geolocator

========================================================

========================================================

Windows location permission must be requested properly.

On first launch, show a small foreground application window.

The application must call:

Geolocator.RequestAccessAsync()

from the foreground UI context.

Do not attempt to bypass Windows privacy controls.

If Windows displays its location permission prompt, allow the normal Windows consent experience to occur.

Display the returned access state:

Allowed
Denied
Unspecified

"Location permission is disabled. Enable location access in Windows Settings."

Also provide a button:

[Open Location Settings]

that opens the appropriate Windows Location privacy settings page if possible.

========================================================
GET THE MOST PRECISE LOCATION POSSIBLE
========================================================

When retrieving location, create a new Geolocator instance.

Configure it to request high accuracy.

Use:

DesiredAccuracy =
Windows.Devices.Geolocation.PositionAccuracy.High

and where appropriate set:

DesiredAccuracyInMeters = 10

Do not claim that Windows will actually achieve 10 meter accuracy.

That value is a REQUEST to Windows for better accuracy.

Windows decides what positioning technology is available.

Call GetGeopositionAsync using an appropriate maximum age and timeout.

Use a reasonable configuration such as:

MaximumAge:
0 to 30 seconds

Timeout:
30 seconds

Prefer a fresh location fix over a stale cached result.

If possible, first attempt a fresh high-accuracy position.

If it fails or times out, optionally allow one fallback attempt with slightly less restrictive requirements.

Do not loop forever.

Display:

========================================================
ACCURACY HANDLING
========================================================

Accuracy is critical.

Always save and display Windows' reported accuracy value in meters.

Example:

Latitude: 40.817391
Longitude: -73.941502
Accuracy: 28 meters

Do not round latitude/longitude excessively.

Store at least 6 decimal places.

Prefer retaining the original double precision internally.

Create a quality classification:

EXCELLENT:
accuracy <= 25 meters

GOOD:
accuracy > 25 and <= 100 meters

APPROXIMATE:
accuracy > 100 and <= 1000 meters

LOW:
accuracy > 1000 meters

UNKNOWN:
no accuracy value available

Save this as:

accuracyQuality

========================================================
TRY TO IMPROVE THE LOCATION FIX
========================================================

When the user presses Get Location:

1. Request one high accuracy position.

2. If multiple position updates can be obtained safely within approximately
15-30 seconds, collect several readings.

3. Compare their reported accuracy values.

4. Keep the reading with the LOWEST accuracy radius value.

For example:

Reading 1 accuracy: 250m
Reading 2 accuracy: 75m
Reading 3 accuracy: 22m

Save Reading 3.

Do not average coordinates blindly.

Use Windows' reported accuracy to choose the best result.

Stop early if an excellent fix is obtained.

Example:

accuracy <= 20 meters

Do not continue requesting location unnecessarily after a sufficiently precise reading has been obtained.

========================================================
LOCAL OUTPUT
========================================================

Create:

C:\ProgramData\LESLocationAgent\

Write the most recent successful location to:

C:\ProgramData\LESLocationAgent\location.json

Example:

{
  "latitude": 40.817391,
  "longitude": -73.941502,
  "accuracyMeters": 28.4,
  "accuracyQuality": "GOOD",
  "altitudeMeters": null,
  "altitudeAccuracyMeters": null,
  "headingDegrees": null,
  "speedMetersPerSecond": null,
  "positionSource": "WiFi",
  "locationSource": "Windows Geolocation",
  "permissionStatus": "Allowed",
  "timestampUtc": "2026-08-11T18:35:42Z",
  "computerName": "LES-LAPTOP-001",
  "agentVersion": "1.0.0"
}

Use valid JSON.

Write JSON atomically:

1. Write to a temporary file.
2. Replace location.json only after the new file is complete.

This prevents Action1 from reading a partially-written JSON file.

========================================================
STALE LOCATION HANDLING
========================================================

Never overwrite a valid existing position with empty or invalid coordinates.

If a location request fails:

retain the last successful coordinates.

Create a separate status file:

C:\ProgramData\LESLocationAgent\status.json

Example:

{
  "lastAttemptUtc": "...",
  "lastSuccessUtc": "...",
  "permissionStatus": "Allowed",
  "locationStatus": "TimedOut",
  "error": null
}

This lets Action1 distinguish:

- no location ever acquired
- location currently unavailable
- last location is stale
- permission denied

========================================================
AUTOMATIC LOCATION UPDATES
========================================================

After the user has granted location permission, support automatic refresh.

Because Windows location permission is user/application-context sensitive, DO NOT build this solely as a LocalSystem Windows service.

Use a supported logged-in-user mechanism.

Preferred design:

- small WinUI application
- starts automatically when the user signs in
- normally runs minimized
- periodically requests a location update

Initial refresh interval:

15 minutes

Make this setting configurable in:

C:\ProgramData\LESLocationAgent\config.json

Example:

{
  "refreshMinutes": 15,
  "desiredAccuracyMeters": 10,
  "locationTimeoutSeconds": 30
}

Minimum permitted refresh interval:
5 minutes

Do not request location continuously every few seconds.
